# NPCS — Easy NPC, as it actually is

> How to build an NPC in this pack. **Every fact below was read out of the installed jar**,
> not recalled — the schema in §④ is the mod's own shipped preset, copied verbatim.

---

## ① DIGEST

**What is installed.** `easy_npc` **7.10.0**, NeoForge 1.21.1, in three jars: `easy_npc`
(core), `easy_npc_bundle`, `easy_npc_config_ui`. 65 entity types, ~40 commands under
`/easy_npc`, and a **preset system that is a datapack** — which is how this project should
define its characters, because every other datapack here is already generated by a tool.

**The one thing to understand first.** An NPC is not built in code. It is a **preset**: one
SNBT file holding the entity type, the skin, the objectives, the attributes and the dialogue
hooks. You write the file, the mod spawns from it. Nothing needs a GUI and nothing needs to
be done by hand in game.

**What Ank needs, and all three exist** (§⑥): `Invulnerable: 1b` for unkillable,
`FOLLOW_PLAYER` with `StartDistance`/`StopDistance` for the following, and
`PersistenceRequired: 1b` so he does not despawn. No custom code required for any of it.

**⚠️ What is NOT proved.** Everything here is read from the jar, which tells you what the
mod *accepts*, not what it *does*. The follow behaviour, the spawn, and whether a datapack
preset is picked up from our own pack all need the game — they are declared as `NEEDS-GAME`
markers and show up in `node tools/prefire.js`.

**The skins are in and the route is settled** (§⑤). All three Act 0 characters were already
drawn — Ank, Caebrim and Alice, 64×64 — and now ship through the same path as the god fonts.
`SkinData: { Type: "RESOURCE_LOCATION" }` pointing at `veldora:textures/entity/<name>.png`.

## ③ WHAT IS INSTALLED

**65 entity types**, in three families:

| family | examples | use |
|---|---|---|
| humanoid | `easy_npc:humanoid` · `humanoid_slim` · `player` · `orc` · `fairy` | 🔑 **what a character wants** |
| vanilla-shaped | `zombie` · `skeleton` · `villager` · `allay` · `cat` · `horse` | ambience, livestock |
| `[EF]` Epic Fight | `epic_fight_humanoid_raw` and 16 others | combat-capable, animated |

⭐ **`easy_npc:humanoid` is the one to build Ank on.** `humanoid_slim` is the Alex-model
variant; `player` exists but carries player-skin machinery that is not needed for an NPC
that is never a player.

⚠️ **The `[EF]` variants are not free.** They exist because Epic Fight is installed and they
bring its animation and combat rig with them. Ank does not fight anybody in Act 0, so the
plain humanoid is both simpler and one less system to reason about.

## ④ THE PRESET — the schema, verbatim

> ⭐ **This is the mod's own file**, `data/easy_npc/api/preset/base/humanoid.npc.snbt`,
> copied unedited. It is the authoritative shape; everything else here is commentary on it.

```
{
  PresetMetadata:{
    access:"INTERNAL", author:"Easy NPC", category:"Base",
    created:1L, description:"", entityTypeId:"easy_npc:humanoid",
    modified:1L, name:"entity.easy_npc.humanoid Base",
    variantType:"STEVE", version:"1.0.0"
  },
  data:{
    ActionData:{ ActionEventSet:{ ON_INTERACTION:[
      { Type:"OPEN_DEFAULT_DIALOG" }, { Type:"OPEN_TRADING_SCREEN" } ] } },
    ArmorDropChances:[0.085f,0.085f,0.085f,0.085f],
    ArmorItems:[{},{},{},{}],
    Brain:{ memories:{} },
    CanPickUpLoot:0b,
    CustomNameVisible:1b,
    EasyNPCVersion:3,
    HandDropChances:[0.085f,0.085f],
    HandItems:[{},{}],
    Invulnerable:0b,
    LeftHanded:0b,
    ModelData:{},
    ObjectiveData:{ ObjectiveDataSet:[
      { Type:"LOOK_AT_RESET" }, { Type:"LOOK_AT_PLAYER" }, { Type:"LOOK_AT_MOB" } ] },
    PersistenceRequired:1b,
    SkinData:{ Type:"DEFAULT" },
    Status:{ finalized:1b },
    VariantType:"STEVE",
    id:"easy_npc:humanoid"
  }
}
```

### Where a preset lives

| location | path | what it is for |
|---|---|---|
| **datapack** | `data/easy_npc/preset/…` | ⭐ **ours.** Ships with the pack, versioned in git, generated by a tool |
| the mod's own | `data/easy_npc/api/preset/base/` | 65 shipped defaults. Read them; do not edit them |
| config | `config/easy_npc/preset/<entity_type>/` | per-instance, hand-made. Every folder is currently **empty** |
| world | inside the world save | exported from a live NPC |

Formats: **`.npc.snbt`** (readable — use this), `.npc.json`, `.npc.nbt`.

⚠️ **`access:"INTERNAL"` is the mod's own marker.** Ours should not claim it; the field is
part of a security model (`CommandAuthority`, `PresetCommandSecurity` in the jar) and
pretending to be internal is asking for a surprise later.

## ⑤ WHAT THE MOD CAN BE TOLD TO DO

### Commands — root `/easy_npc`

Read off the command classes in the jar, so this is the complete set:

```
spawn  respawn  despawn  delete  spawner       existence
preset  (import / export / generate)           definition
objective  navigation  position  rotate  pose  movement
dialog  interact  trading  progression         interaction
skin  render  scale  animation  name  equipment  look
attribute-ish: faction  state  owner  sound
debug  info  list  stats  test  reload  pause
```

### Objectives — the behaviour vocabulary

**54 types.** The ones that matter for a character who is not fighting:

| | |
|---|---|
| **follow** | `FOLLOW_PLAYER` · `FOLLOW_OWNER` · `FOLLOW_ENTITY_BY_UUID` · `FOLLOW_ITEM` |
| **look** | `LOOK_AT_PLAYER` · `LOOK_AT_MOB` · `LOOK_AT_RESET` · `LOOK_RANDOM_AROUND` |
| **wander** | `RANDOM_STROLL` · `RANDOM_STROLL_AROUND_HOME` · `WATER_AVOIDING_RANDOM_STROLL` |
| **avoid** | `FLEE_PLAYER` · `FLEE_MONSTER` · `FLEE_SUN` · `AVOID_SUN` · `PANIC` |
| **doors** | `OPEN_DOOR` · `CLOSE_DOOR` · `MOVE_BACK_TO_HOME` |
| **combat** | `MELEE_ATTACK` · `BOW_ATTACK` · `ATTACK_PLAYER` · `HURT_BY_TARGET` … ⛔ none for Ank |

Each entry is a compound taking `Type` plus any of:

```
StartDistance  StopDistance  SpeedModifier  TeleportDistance  FollowOffset
LookDistance   Priority      Probability    Interval
MustSeeTarget  MustReachTarget  OnlyAtNight  OnlyWithoutOwner
TargetPlayerName  TargetEntityUUID  TargetOwnerUUID  TargetTeamName  TargetItemTag
```

### Attributes

**Combat:** `isInvulnerable` · `isAttackableByPlayers` · `isAttackableByMonsters` ·
`isAttackableByFactions` · `isExplosionResistant` · `isKnockbackResistant` ·
`healthRegeneration`. Grouped alongside base, environmental, interaction and movement sets.

🔑 **For unkillable, prefer the vanilla `Invulnerable:1b` in the preset data.** It is in the
shipped schema above, so it is certain to be read. The mod's `isInvulnerable` attribute
exists too and is likely equivalent — but one is proven present in a file the mod itself
ships, and the other is inferred from a method name.

### Skins

`DEFAULT` · `PLAYER_SKIN` · `RESOURCE_LOCATION` · `SECURE_REMOTE_URL` ·
`INSECURE_REMOTE_URL` · `CUSTOM` · `NONE`, with `SkinData` taking a texture, URL, UUID or
name depending on type.

⚠️ **`INSECURE_REMOTE_URL` fetches over plain HTTP.** Do not use it for a shipped pack.

### ⭐ OUR SKINS, AND THE ROUTE THEY TAKE

Three exist, all 64×64 (the modern format, so slim arms are available):

| character | resource location |
|---|---|
| Ank | `veldora:textures/entity/ank.png` |
| Caebrim | `veldora:textures/entity/caebrim.png` |
| Alice | `veldora:textures/entity/alice.png` |

They live at `pack/resourcepacks/veldora/assets/veldora/textures/entity/` and reach players
through `python tools/build_client_assets.py --build`, which copies the whole assets tree
into `clientpack/kubejs/assets/`.

🔑 **This is the route the god fonts already proved**, and it is the only one that works
here. KubeJS loads `kubejs/assets/` as an **always-active** resource pack — nothing to
enable, nothing for a player to forget. ⛔ A server-push resource pack is not an option on
this pack at all: applying one forces a full client resource reload, and on 300+ mods that
exceeds Minecraft's 31-second configuration-phase timeout and drops the player.

⚠️ **Filenames are lowercase because they must be.** A Minecraft resource location accepts
`[a-z0-9_./-]` only, so `Ank.png` cannot be addressed at all. The originals in
`C:\MCServer\Skins\` are title-case and were renamed on the way in.

🔴 **COPYING IS NOT LOADING.** Minecraft builds its asset set once per resource reload, so a
client that was already running has not seen them — and for fonts the symptom was not
vanilla text but TOFU, every glyph a missing-box, because an absent font yields an empty set
rather than a fallback. F3+T or relaunch. A texture behaves the same way.

## ⑥ WHAT ANK NEEDS

Ethan, 2026-09-05: *"Ank should spawn on the upper layers of the caves, he should be
unkillable, and follow the player around until they hit the second layer. this is just intro
behavior, he will have more later."*

Every part of that is a preset field. **No custom entity code is required.**

| the requirement | how |
|---|---|
| unkillable | `Invulnerable: 1b` — and `isAttackableByPlayers: false` so he does not even flinch |
| follows the player | `ObjectiveDataSet: [{ Type:"FOLLOW_PLAYER", StartDistance:…, StopDistance:… }]` |
| does not despawn | `PersistenceRequired: 1b` — already `1b` in the shipped default |
| looks at you | `LOOK_AT_PLAYER` + `LOOK_AT_RESET`, as the default preset does |
| stops at the second layer | ⛔ **not a preset field.** A y-band check that removes the follow objective — the one part of B1–B3 that is ours to write |
| never fights | no attack objective, and `isAttackableByMonsters: false` so the cave cannot start one |

🔑 **The layer boundary is the only custom logic.** `help.js` gives the strata the game
already tells the player: **0 to −32 the old diggings · −32 to −52 the deep works · −52 to
−64 the sealed floor.** "Upper layers" is the diggings; "the second layer" is −32.

⚠️ **That number is not mine to assume.** It is the band the game already names, which makes
it the honest default — but it is a design number and it belongs in `ACT0.md`'s ledger, not
buried in a preset.

## ⑦ WHAT IS READ, INFERRED, AND UNPROVEN

> ⭐ The most important section. Everything above sounds equally confident and is not.

**READ from the jar** — the entity list, the command classes, the objective types and their
field names, the attribute names, the skin types, and the preset schema in §④, which is a
shipped file copied byte for byte.

**INFERRED** — that a datapack under `data/easy_npc/preset/` is loaded from *our* pack. The
jar shows the loader reading `easy_npc/preset` and its own presets sitting under
`data/easy_npc/api/preset/base/`, which is a slightly different path. ⚠️ **The two may not be
the same folder**, and the first thing to test is whether a preset we ship is found at all.

**UNPROVEN, and only the game can settle it** — whether `FOLLOW_PLAYER` picks the nearest
player or needs `TargetPlayerName`; whether removing an objective at runtime stops an NPC
already following; whether `Invulnerable` also blocks void and `/kill`. Each is a
`NEEDS-GAME` marker and appears in `node tools/prefire.js`.

<!-- NEEDS-GAME: a preset we ship under data/easy_npc/preset is found at all :: /easy_npc preset list -->
<!-- NEEDS-GAME: the skins render on an NPC, not as a missing texture :: F3+T then /easy_npc spawn -->
<!-- NEEDS-GAME: FOLLOW_PLAYER targets the nearest player without TargetPlayerName :: /easy_npc objective set follow -->
<!-- NEEDS-GAME: Invulnerable:1b survives void and /kill, not just damage :: /kill @e[type=easy_npc:humanoid] -->
<!-- NEEDS-GAME: removing the follow objective stops an NPC already following :: /easy_npc objective remove -->

⛔ **Nothing in this file has been run.** The mod is installed and the server is off, which
is the correct state — but it means §⑥ is a plan, not a result.
