# Simple Voice Chat — the one setting that breaks through a tunnel

`voicechat-server.properties` is generated by the mod on first boot. Only one
field needs changing, and it is **not** obvious:

```properties
voice_host=
```

## Why it matters

Voice chat does not travel over the Minecraft connection. It uses its own
**UDP** socket on its own port (24454 by default). When a player joins, the
server *tells* the client where to send voice.

With `voice_host` empty, the server advertises the address and port it sees
locally — `<server>:24454`. Behind a tunnel (playit.gg, ngrok) or a NAT with
port translation, that address is wrong from the outside, so:

- the game works perfectly
- **nobody can hear anyone**
- there is no error that points at the cause

Which reads as a broken mod rather than a missing setting.

## The fix

Set it to the **externally reachable** host and port of your voice tunnel:

```properties
voice_host=your-tunnel-hostname.tun.ply.gg:47389
```

The port here is the **tunnel's external port**, which is usually *not* 24454.
`port=24454` stays as it is — that is what the server binds locally; `voice_host`
is only what it advertises.

## Why the real value is not in this repo

This repository is public. The live value is a directly reachable address for
the server, so it lives in the instance only:

```
<instance>/config/voicechat/voicechat-server.properties
```

That path is gitignored. If you rebuild the instance from scratch, re-apply it —
it is the single easiest thing to forget, and its failure mode is silent.

## Verifying

Restart the server after changing it (the value is read at startup, not
reloadable), then have someone connect from outside your network and speak. In
their Simple Voice Chat settings the connection indicator should show connected
rather than retrying.
